# Managed first-run runtime (local implementation)

This phase is local and inference-only. No Developer ID signing, notarization, upload, tag change or publication is authorized. The app contains only original orchestration code and a pinned artifact manifest; it does not contain Python, wheels, FFmpeg or model weights.

## Native experience

On launch, VoxAster checks its managed installation; if none exists it validates the legacy `~/Documents/OmniVoice-Mac/.venv` and pinned models without moving them. A usable legacy runtime continues working. Otherwise **Set up VoxAster** explains download/storage requirements and the existing model restrictions before setup starts. Setup shows stages, aggregate download progress, Cancel, Retry and a diagnostic-log link. Settings offers setup/repair again after dismissal. Repair preserves the old installation and every user-data directory.

OmniVoice weights remain **CC-BY-NC, version unspecified in the pinned card**. Boson's community agreement and incorporated Meta licence/AUP remain unchanged, including the 100,000 annual-active-user condition. Setup displays these restrictions and requires the user to confirm review/eligibility. No unrestricted commercial-use claim is made.

## Storage and activation

Private root: `~/Library/Application Support/OmniVoice/managed-runtime/v1/`.

- `downloads/`: complete hash-verified upstream artifacts; retained for retry/repair. An interrupted `.partial` is restarted; this is file-level reuse, not HTTP byte-range resume.
- `staging/<UUID>/`: private standalone Python, installed wheels, base model and tokenizer assembled for validation.
- `installations/<UUID>/`: completed generations, including `installation.json`, exact file hashes, architecture, compatible app/runtime schema, source provenance and installation time.
- `active.json`: atomically replaced pointer; previous generations are retained.
- `state.json`: installation progress/ready record; partial data never qualifies as an active installation.
- `logs/`, `cache/`, `temporary/`: mutable diagnostic, optional model/Numba cache and temporary inference data outside the app and completed runtime.

Promotion is staging-directory rename followed by atomic activation after hashes/imports/provenance pass. A process-level file lock prevents concurrent installers. Crashes before activation leave the previous pointer intact; a retry uses a fresh stage and reuses valid downloads. A crash can leave an inactive stage/generation; it is never treated as ready. Repair currently rebuilds the environment as a unit, reusing individually verified downloads, rather than mutating a potentially running Python installation in place. It does not auto-delete old runtimes or orphan stages. This deliberately costs storage and preserves recovery options.

The installer does not touch the legacy venv, saved engines, voices, projects, generated audio, preferences, drafts or installed application. No runtime migration moves gigabytes automatically. A later schema can coexist and switch only after validation.

## Integrity and network boundary

`Backend/bootstrap-lock.json` is the complete 103-artifact lock: URL, version/revision, filename, byte count, SHA-256, unpacked size, licence/source and model destination. It is bundled as an original configuration resource. All existing `runtime.json` pins remain exact, including the official Boson revision and weight hash. No mirror fallback exists.

Python is fetched with URLSession, HTTPS and a redirect-host allowlist, then SHA-256/size checked before extraction or execution. Remaining downloads use the standalone interpreter's standard library and pip's included CA roots, strict HTTPS, and a redirect allowlist. No user URL or shell command is accepted. Allowed hosts are GitHub/codeload/release assets, `files.pythonhosted.org`, Hugging Face and its named LFS/Xet CDN hosts. An unrecognised future CDN fails closed and requires a reviewed update.

The app installs the exact downloaded wheel files with `--no-index --no-deps --no-compile`. The pinned OmniVoice commit archive is built locally with pinned pure-Python Hatchling tooling, `--no-build-isolation`, without Git or a compiler. Pip's installed archive hash is checked against the bundled lock to establish commit provenance; it is not relabelled as a VCS checkout. No dependency resolution or floating index lookup occurs on the user's Mac. Build tools and notices remain in the managed environment.

Before activation: `pip check`, Python version/architecture, imports, MPS, FFmpeg execution, complete model hashes and package/model/tokenizer provenance. Every later managed startup checks its installation receipt against all runtime files, then imports/provenance before backend startup. The native app checks the interpreter's recorded hash before executing it. Receipts detect corruption; they are not a defence against an attacker already able to rewrite all files belonging to the same user.

The checkpoint review additionally rejects symlinks, special files and hard-linked write targets in managed storage, and rejects runtime storage anywhere inside an `.app`. Managed child processes use an external working directory and strip inherited interpreter, pip, dynamic-loader, archive and cache overrides before applying explicit managed settings. The download manifest is validated natively before the initial download as well as in the Python installer. Runtime-internal relative links from the reviewed Python distribution remain supported and are checked by the receipt inventory.

The exact cached 103 artifacts were re-hashed against the lock. Inspection of all 32,002 archive members found no absolute/traversing paths, external links, special nodes or set-ID tar entries; the 10 Python links resolve within the archive. Extraction uses macOS bsdtar's default traversal/symlink protections (never `-P`), `--no-same-owner` and `--no-same-permissions`, into a fresh managed stage after the exact archive hash passes. Changing an archive pin requires repeating this artifact-content review. The installer is not a security boundary against a malicious process running as the same user and racing/replacing all of that user's files.

Offline startup uses verified local base/tokenizer assets. Optional Whisper transcription retains the prior on-demand download behavior; supplying reference text avoids that download. Optional F5 is not installed. This phase does not promise offline optional transcription before its separate assets are cached.

## Licence gate: direct upstream installation, not app bundling

The chosen Python archive's licence files, wheel licence texts/METADATA and upstream notices were inspected before enabling installation. Copies remain in the installed upstream distributions. This is a direct end-user download/install flow: VoxAster does not host or redistribute those binaries inside its app. It does not confer permission to later mirror, bundle or redistribute them without satisfying all notices/source obligations.

- CPython 3.12.15 from Astral python-build-standalone release 20261003: PSF and bundled dependency licences, pip/vendor notices. The build project itself is MPL-2.0; that alone is not the runtime's complete licence. [Publisher licensing notes](https://github.com/astral-sh/python-build-standalone/blob/20261003/docs/running.rst).
- PyTorch 2.8.0 and torchaudio 2.8.0: BSD-family core with their included third-party notices, including native code. No CUDA/NVIDIA Linux packages are selected for macOS.
- `imageio-ffmpeg` 0.6.0: BSD-2-Clause wrapper, but its exact arm64 FFmpeg **7.1** executable reports **GPL-2.0-or-later** with `--enable-gpl`. It is a separate subprocess downloaded from the publisher's PyPI wheel; it is not a BSD-only component. No `--enable-nonfree` is present. Do not bundle/mirror this wheel without the corresponding GPL redistribution review and source obligations. [Publisher](https://github.com/imageio/imageio-ffmpeg/tree/v0.6.0), [FFmpeg terms](https://ffmpeg.org/legal.html).
- SoundFile contains LGPL libsndfile; SoXR is LGPL; SciPy includes native-library notices/runtime exceptions; llvmlite includes LLVM's exception; certifi/pathspec/orjson include MPL terms. These are not silently relicensed as MIT.
- OmniVoice source and model terms remain separate. The app adds no training UI, dataset extraction, LoRA, merging or training installation extras. The upstream package's contents remain upstream code; no training entry point is surfaced by this application.

## Sizes

The pinned upstream download total is **3,556,708,734 bytes (3.31 GiB)**. Archive-member/model sizes total **4,264,718,288 bytes (3.97 GiB)** before installer metadata/local build output. Retaining the downloaded archives adds 3.31 GiB. The native preflight requires downloads plus twice the unpacked payload (**12,086,145,310 bytes, 11.26 GiB**) for initial staging/build headroom; it does not delete prior installations to make room. The real installed generation measured **4,269,509,467 logical bytes (3.98 GiB)**, or **4,244,228 KiB allocated** on this APFS volume. Its retained downloads measured **3,489,868 KiB allocated**. Together that is about **7.38 GiB allocated**, excluding older generations, logs, optional caches and temporary staging. These measurements come from the new managed installation, not the previous developer venv. Network protocol overhead is excluded.
